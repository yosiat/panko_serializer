# Dump-to-file

Two distinct tools with distinct expectations:

## Console inspection

*Goal: quickly see what got generated for a given **Descriptor**, from a Pry / IRB / Rails
console.*

Because the emitted source is installed into its class via Ruby's standard class-level
source-injection API with a synthetic `__FILE__` path, `Method#source_location` returns
something usable, and the [`method_source`](https://github.com/banister/method_source) gem
can retrieve the source:

```ruby
serializer.method(:_write_one).source
# => "def _write_one(record, writer, context, filters)\n  writer.push_object\n  ..."
```

In Pry: `show-source serializer._write_one` displays the generated source inline.

No additional work beyond ensuring the synthetic path is passed at generation time.
Works out of the box.

## Dump to file

*Goal: produce a `.rb` file that a human (or coding agent) can read, modify, and run.*

### Contract: the dumped file is runnable with a Descriptor at construction

The **Dump**ed file is the **exact same class definition** that the in-memory compiled form
produces — no divergence. When loaded, the class can be instantiated and used, provided a
**Descriptor** is supplied at `.new`:

```ruby
require_relative "post_serializer_json.generated"
PostSerializer_JSON.new(descriptor: my_descriptor).serialize_one(@post)
```

The **Descriptor** is the **Environment** — it resolves:

- **Method Attribute** bodies (every **Callable** referenced by the generated code).
- **Association** `if:` **Callables**.
- Nested **Descriptors** needed to construct nested **Generated Class** instances.

Since Panko owns its **Descriptors**, it always has one available to hand in.

### Dumped file shape

```ruby
# frozen_string_literal: true
#
# Generated by serializers-code-gen
# Descriptor: PostSerializer
# Mode: :json
# Config: null_for_missing_has_one=true, supports_root_key=false
#
# To use:
#   require_relative "post_serializer_json.generated"
#   PostSerializer_JSON.new(descriptor: descriptor).serialize_one(record)

class PostSerializer_JSON
  def initialize(descriptor:)
    @cb_full_title       = descriptor.method_attributes[0].body
    @cb_if_comments      = descriptor.associations[0].if
    @comments_serializer = CommentSerializer_JSON.new(descriptor: descriptor.associations[0].descriptor)
  end

  def serialize_one(record, context: nil, filters: nil)
    writer = Oj::StringWriter.new(mode: :rails)
    _write_one(record, writer, context, filters)
    writer.to_s
  end

  def _write_one(record, writer, context, filters)
    writer.push_object
    writer.push_key("id")
    writer.push_value(record.id)
    writer.push_key("full_title")
    writer.push_value(@cb_full_title.call(record, context))
    if @cb_if_comments.call(record, context)
      writer.push_key("comments")
      @comments_serializer._write_one(record.public_comments, writer, context, filters)
    end
    writer.pop
  end

  # ... serialize_many omitted for brevity
end
```

### Dumping API (shape TBD)

Candidates:

```ruby
# On the compile result:
klass = SerializersCodeGen.compile(descriptor, output: :json)
klass.dump_to("app/generated/post_serializer_json.rb")

# Or as a standalone utility:
SerializersCodeGen.dump(descriptor, output: :json, to: "app/generated/...")

# Or a CLI (later phase):
# $ serializers-code-gen dump PostDescriptor --output=json --to=app/generated/
```

Exact API to be decided. The core requirement is that the function produces a file whose
contents are identical to what `module_eval` runs for the in-memory compile — same line
numbers, same characters.

### Nested Descriptor dumps

When a **Descriptor** has **Associations**, the **Generated Class** for the inner
**Descriptor** must also exist in Ruby land at load time. Two options:

1. **Dump all Generated Classes involved into separate files** in topological order; the
   outermost `require_relative`s each inner class.
2. **Dump everything into a single file** with all classes defined in the correct order.

Default: (1), single file per **Generated Class**, with explicit `require_relative` directives.
More modular and matches the "one file per class" Ruby convention.

## Not in v1: fully self-contained dumps

A **Dump** that bakes **Callable** source directly into the file (so the file has zero
external dependencies beyond Oj and stdlib) is a future enhancement. It requires recovering
Proc source via the `method_source` gem and only works when the **Callable** is written in
a way that `method_source` can recover (real method definitions; inline lambdas usually OK;
dynamically-built procs not). See [deferred.md](deferred.md).
